# Contributing

Thanks for looking at DNApps. During the comment period the most useful
contributions are:

- **"This already exists."** Point us to it. We'd rather build on existing
  work than compete with it.
- **"This part is wrong or missing."** Open an issue about one specific
  section of the spec and quote it.
- **Build reports.** Build a capsule with your agent and tell us what
  happened: which agent, how long it took, whether the tests passed, and what
  the agent had to guess. Use the "Build report" issue template.
- **New example capsules.** Small, real apps are best. Each one should
  validate against `schema.json` and include a test harness, as described in
  `guide.md`.

## Pull requests

- Keep a pull request to one change.
- For anything beyond a typo, open an issue first so we can discuss it.
- By contributing you agree that your contribution is licensed under the
  license of the file you change (CC BY 4.0 for text, Apache-2.0 for the
  schema, and the license stated inside an example capsule) and is covered by the patent pledge.

## Conduct

Criticize the ideas, not the people, and say exactly which line you mean.
